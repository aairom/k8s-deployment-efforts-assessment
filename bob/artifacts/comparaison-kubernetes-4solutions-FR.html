1. Résumé Exécutif

Cette analyse compare les quatre solutions Kubernetes les plus représentatives du marché, des services entièrement managés aux déploiements autogérés sur infrastructure propre.

Le choix optimal dépend du contexte organisationnel : cloud existant, exigences réglementaires, expertise interne et stratégie à long terme.

2. Vue d'ensemble des Solutions

IBM Kubernetes Service (IKS)

Kubernetes vanilla certifié CNCF — IBM Cloud

  • Plan de contrôle dédié, géré par IBM
  • Nœuds Ubuntu 22.04 LTS / RHEL 8
  • Runtime containerd, CNI Calico
  • Intégration IBM Cloud IAM, Key Protect, ICR
  • ISO 27001, SOC 2, PCI DSS, HIPAA
  • Coût d'entrée le plus bas (IBM Cloud)
ROKS — Red Hat OpenShift on IBM Cloud

OpenShift Container Platform 4.x managé — IBM Cloud

  • Plan de contrôle OCP dédié, géré par IBM
  • Nœuds RHCOS immutables, SELinux enforcing
  • Runtime CRI-O, SCC par défaut
  • OperatorHub, Tekton, S2I, Web Console intégrés
  • Requis pour les IBM Cloud Paks
  • FIPS 140-2, FedRAMP, DoD CC SRG
Kubernetes Auto-Géré

On-premises / IaaS non managé — Infrastructure propre

  • Contrôle total : version, configuration, composants
  • kubeadm, k3s, RKE2, Talos, Rancher…
  • Charge opérationnelle maximale (etcd, PKI, CNI, CSI)
  • Aucune dépendance fournisseur
  • Adapté air-gapped et souveraineté des données
  • Expertise SRE avancée indispensable
Amazon EKS

Kubernetes managé certifié CNCF — Amazon Web Services

  • Plan de contrôle multi-AZ managé par AWS
  • EC2 Managed Node Groups + Fargate (serverless)
  • AWS VPC CNI (IPs VPC natives pour les pods)
  • Intégration IAM AWS, EBS/EFS/FSx, ECR, ALB
  • EKS Anywhere pour on-premises
  • SOC, PCI, ISO, HIPAA, FedRAMP

14. Recommandations par Profil

Profil 1 — Entreprise native IBM Cloud

→ IKS ou ROKS

  • IKS si workloads conteneurisés purs, coût minimal, équipes K8s expertes
  • ROKS si IBM Cloud Paks, secteur réglementé (FIPS, FedRAMP), OpenShift hybride
  • ROKS si expérience développeur enrichie souhaitée
  • BYOL Red Hat : ROKS au coût d'IKS
Profil 2 — Organisation hybride / Multi-Cloud

→ ROKS (via IBM Cloud Satellite)

  • Cohérence opérationnelle IBM Cloud ↔ on-premises ↔ autres clouds
  • Même CLI oc, SCC, OperatorHub dans tous les environnements
  • IBM ACM pour gouvernance centralisée multi-clusters
  • IBM Cloud Paks sur Satellite
Profil 3 — Organisation native AWS

→ Amazon EKS

  • Déjà investi dans l'écosystème AWS (IAM, VPC, RDS, S3, Lambda)
  • Intégration native tous services AWS + AWS Marketplace
  • Fargate pour workloads serverless sans gestion nœuds
  • Karpenter pour optimisation coûts EC2
Profil 4 — Souveraineté / On-Premises obligatoire

→ Kubernetes Auto-Géré

  • Exigences réglementaires interdisant le cloud public
  • Infrastructure propre à valoriser (CAPEX déjà engagé)
  • Distribution commerciale recommandée (Rancher, Tanzu)
  • ⚠️ TCO réel souvent sous-estimé — expertise SRE indispensable
